# Working conventions for coare-seaice

Read this before doing anything in the repository. It applies to every Claude session
and subagent.

## What this is

A Python package that extends the COARE bulk flux algorithm to sea ice and the marginal
ice zone (MIZ). It depends on `pycoare` for open water. Owner: Chris Barrell (UEA), with
Ian Renfrew. Design documents are in `docs/design/`; the task backlog is `TASKS.md`.

## Rules that are never broken

1. **This repository is public. Never commit campaign data, restricted ROVER data, ERA5
   or satellite files, or paper PDFs.** The `.gitignore` and the pre-commit check enforce
   this; do not weaken them. Small public test files go in `tests/fixtures/` only.
2. **Never fabricate numbers or citations.** Quote equation and table numbers from the
   papers. Label anything from memory as unverified.
3. **Describe a change before making it** when it alters results, and wait for Chris to
   confirm. Record every result-changing change in `CHANGELOG.md` with its size.
4. **Nothing irreversible without Chris's explicit go-ahead:** releases, registering the
   package name, messages to other people, changing repository settings.
5. **Flag suspect data, do not adjust it.** NaN in gives NaN out. No silent default fills.

## How Chris works

- Experienced scientific programmer (Python, Jupyter, HPC), new to software-engineering
  practice. **Explain each software-engineering choice briefly and in plain terms.**
- Works through the browser (Claude Code on the web, claude.ai). Heavy data processing
  runs on a UEA Linux machine with Python 3.10; data live there and are found through the

- On that machine, xarray `.interp` / `.sel` on ERA5 `valid_time` fails, so colocation is

## Conventions

- **Simple first.** Every new option must be comparable against the simple reference
  (two tiles, ice at min(T_air, -1.8 C), z0_ice = 5e-4 m, COARE stability functions).
  Use complexity only when needed and state its caveats.
- **Sign convention:** heat fluxes are positive upward, as in COARE.
- **Outputs are named,** following `pycoare` names (`tau`, `hsb`, `hlb`, `usr`, ...).
- **Logging:** scripts and generated notebooks write a log to `outputs/logs/<name>.log`.
- **Notebooks** are generated by `build_*.py` builders and never edited or committed.
- **Script configs** default to `REPROCESS = True`.
- **Methods details** (colocation, interpolation, averaging, binning) are always written
  into the docs.
- **Figures:** white backgrounds; legends inside panels; any sea-ice-concentration colour
  map runs dark blue at 0 to white at 1; no explanatory text on figures (caveats go in the
  methods docs).

## Scientific caveats that must stay in the documentation

- **ERA5 downwelling longwave is probably too high** over this region because ERA5
  overestimates cloud. It is not corrected. Results using ERA5 longwave are the warm end
  of a range.
- **Ice roughness is regional and rarely measured.** It is an input with an uncertainty
  range, not a constant.
- **The thin-ice fraction has no routine measurement.** For ships it is a sensitivity
  parameter.
- **Very stable conditions:** the stability functions are validated only up to a bulk
  Richardson number of about 0.2 (Grachev et al. 2007). Flag results beyond that.
- **Ship measurement heights (20-40 m)** are often above the surface layer in stable
  conditions. Flag, do not hide.
- **SHEBA is not independent evidence** for formulas that were fitted to SHEBA data.
- **Cold season only.** No melt ponds or wet snow.

## Workflow

- `main` is protected by convention: work on a branch, open a pull request, merge when the
  tests pass and Chris has approved.
- One backlog task per branch and pull request. Name branches `task/<id>-<short-name>`.
- Before committing: `ruff check . && ruff format --check . && pytest`.
- Commits made by Claude end with a `Co-Authored-By` trailer naming the model.
- Do not copy code from the NOAA or Blomquist COARE implementations into this package;
  open-water fluxes come from `pycoare`.

## Model tiers for subagents

Definitions are in `.claude/agents/`. Use `sonnet` for implementation, tests, docs and
data-pipeline work; `opus` for physics review and anything that needs careful reasoning.
Each task in `TASKS.md` names its tier.
